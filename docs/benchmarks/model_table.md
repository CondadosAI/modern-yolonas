## Protocol

- **Weights**: the pretrained COCO checkpoints this library downloads, which originate
  from Deci's super-gradients releases. Not weights trained by this project.
- **Accuracy**: full COCO val2017, all 5000 images, `pycocotools`. Input letterboxed to
  640 with aspect preserved; NMS at confidence 0.001 and IoU 0.65. Predictions are mapped
  back to original image coordinates before being compared with the ground truth.
- **Parameters**: `sum(p.numel() for p in model.parameters())`.
- **FLOPs**: `torch.utils.flop_counter` for one 640×640 forward pass, multiplies and adds
  counted separately. Papers that report a "GFLOPs" figure roughly half of these are
  counting multiply-accumulates instead; compare conventions before comparing numbers.
- **Latency**: PyTorch FP16 on an RTX 3060 Laptop, batch 1, model forward only — no
  preprocessing, no NMS — median of 30 runs after 8 warmup runs, synchronous single
  stream. See [the latency matrix](latency_matrix.md) for other runtimes, devices and
  precisions; TensorRT on the same GPU is roughly an order of magnitude faster than the
  PyTorch figure here.

## On comparing this with published leaderboards

Detection leaderboards usually report latency on an NVIDIA T4 with TensorRT at batch 1.
That is not the hardware above, and a latency number is meaningless without its protocol,
so the two columns should not be read side by side. The accuracy columns are directly
comparable — they are the standard COCO val2017 metrics.

## Why these are 0.3 below Deci's published figures

Deci publishes 47.5 / 51.5 / 52.2 for S / M / L. This table measures 47.2 / 51.2 / 51.9
on the same weights: **0.3 below, identically for all three variants.**

A constant offset across three models of different sizes is the signature of an
evaluation-protocol difference rather than an implementation difference — an
implementation bug would not cost every variant the same amount. The known cause is in
`data/coco.py`, which drops `iscrowd` annotations instead of marking them *ignore*. COCO
treats crowd regions as neither object nor background; a detection that correctly fires
inside one currently has no ground truth to match and is counted as a false positive.
The training review [estimated roughly a point](../guides/training-review-2026-09-13.md)
for this; measured, it is 0.3.

Numeric agreement with super-gradients is verified separately and much more tightly —
class scores are bit-identical. See [the parity report](parity.md).
